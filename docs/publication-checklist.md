# AI-no-Te Public Alpha publication checklist

This checklist covers the candidate defined by `public-files.json`. Completing it does not itself publish or push the repository.

- [x] Public Core and Experimental AINOTE Return are visibly separated.
- [x] Confirmed live workflow evidence is distinguished from the executable public preview surface.
- [x] Official text-note creation is separated from parked official image Return.
- [x] The Markdown image probe is reported as stored-but-not-rendered, without claiming permanent lack of support.
- [x] AI-no-Te is identified as an independent project and is not presented as an official AINOTE product.
- [x] Experimental Return is labeled experimental, version-specific, unsupported, outside the published official OpenModel interface, and subject to breakage.
- [x] Documented official Skill/OpenModel capabilities are distinguished from product endorsement, partnership, support, and undocumented Desktop behavior.
- [x] Default Public Core and Experimental Return preview commands perform no external write; Desktop execution requires both the execute command and `--execute`.
- [x] Human Approval remains distinct from Clean/Interpreted selection.
- [x] Original preservation is documented and enforced by the intended flow.
- [x] Credential literals are absent from the public allowlist.
- [x] Private user data, real note content, personal paths, and private identifiers are absent from the public allowlist.
- [x] `ainote_api.py` is not present in the public allowlist or bundled repository files.
- [x] The helper is documented as an explicit local prerequisite that is not bundled and has no established redistribution rights.
- [x] Missing/unreadable installed Skill helper fails clearly; detection uses documented local candidates and never downloads or bundles the helper.
- [x] Supported Public Core environment is documented.
- [x] Experimental compatibility evidence and unknown version fields are documented without guessing.
- [x] Static scan and automated tests pass locally.
- [ ] The final Git diff has been reviewed and publication has been explicitly authorized.
- [ ] Repository host settings, issue policy, and public contact route have been reviewed at publication time.
